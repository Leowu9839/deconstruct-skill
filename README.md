# 🔍 拆穿 | Deconstruct

> **看穿每一个 AI Skill 的底牌。**
> 
> *X-Ray Vision for AI Skills.*

---

## 你敢不敢直接往你的 AI 里装？

GitHub 上几千个 Skill，看起来都很酷。

但：
- 它会不会偷偷把你的数据发到第三方？
- 它有没有隐藏指令，会覆盖你的真实意图？
- 它声称要做 A，实际执行的是 B？
- 它申请的权限，真的都是必需的吗？

**你不可能每个 Skill 都自己读一遍源码。但装进去之前，你总得知道它是什么。**

---

## 这是什么

**拆穿（Deconstruct）** 是一个 AI Skill 的系统性拆解框架。

输入一个完整的 Skill，输出一份**结构化 Markdown 拆解报告**。这份报告同时服务两类读者：

- **人类**：带目录的分层文档，按需跳转，不用从头读到尾
- **AI**：结构化上下文补充文档，帮助理解设计意图、边界条件和脆弱点

### 核心能力

| 能力 | 说明 |
|------|------|
| 🔬 **技术解剖** | 扒出 Skill 用了什么手段——外部 API、MCP、工具调用、知识库、串联方式、持久化机制 |
| 🔐 **安全审计** | 数据流向、外部调用合理性、隐藏指令、权限边界、意图一致性——每项都有 ✅/⚠️/❌ 和白话结论 |
| 🧩 **思维组件提炼** | 把设计决策抽象成可独立复用的组件，每个组件含本质、适用条件、变体、联动 |
| 🧨 **脆弱点分析** | 观察型 + 压力测试型，主动找出最致命的薄弱环节 |
| 🚀 **进化方向** | 插件强化、串联方向、重造取舍——知道从哪里动刀 |

### 安全审计五项检查

```
数据流向        → 你的内容会不会流向第三方？
外部调用合理性   → 每个请求都有业务必要性吗？
隐藏指令        → 有没有劫持角色、覆盖意图的语句？
权限边界        → 申请的权限与功能匹配吗？
意图一致性      → 说要做的事和实际做的是同一件吗？
```

> **每条审计结论都有两部分：技术判断 + 白话说明（"这对你意味着什么"）。**
> 
> 不懂技术的用户，看完也知道「这个 Skill 能不能用」。

## 真实案例

**输入**：某「智能写作助手」Skill 的完整实现

**拆穿输出**：

```markdown
## 📋 概览
> 这是一个帮你把长文章变成要点清单的工具，安全可用，不会发送你的内容给别人。

## 🔬 技术解剖
| 技术层 | 内容 | 白话说明 |
|--------|------|----------|
| 外部 API | 无 | 不连外网 |
| MCP 调用 | 无 | 不调外部工具 |
| 工具调用 | 代码执行（Python） | 用来跑文本分词和统计 |
| 知识来源 | 纯模型内置 | AI 自己记住的语法规则 |
| 串联方式 | 单步生成 | 一次出结果 |
| 持久化 | 无 | 不保存任何记录 |

## 🔐 安全审计
| 审计项 | 状态 | 这对你意味着什么 |
|--------|:----:|------------------|
| 数据流向 | ✅ | 你输入的内容只在对话里处理，不会发给任何第三方 |
| 外部调用 | ✅ | 不需要联网，不需要担心 API 泄露 |
| 隐藏指令 | ✅ | 没有发现覆盖你意图的语句 |
| 权限边界 | ✅ | 只申请文本处理权限，合理 |
| 意图一致性 | ✅ | 声称写作辅助，实际也是写作辅助 |

## 🧩 思维组件
- **组件：分段摘要** — 把长文本拆成块，逐块摘要再合并
- **组件：关键词锚定** — 用 TF-IDF 找高频词，确保摘要不跑偏

## 🧨 脆弱点
- 输入超过 5000 字时，分段边界可能切断语义
- 换到非中文语言，关键词提取准确度下降

## 🚀 进化方向
- 前接：内容抓取 Skill（负责从网页/文档提取原文）
- 后接：排版美化 Skill（负责把摘要变成 PPT/海报）
```

**价值**：5分钟看完报告，知道这个 Skill 安不安全、值不值得学、怎么改更好。

## 设计理念

### 创新一：非技术用户优先

技术用户直接看原始文档就够了。真正需要这份报告的，是看不懂原始实现的人。

- 技术术语首次出现必须附带白话解释
- 安全审计的每条结论必须说明「这对你意味着什么」
- 概览部分必须有一句任何人都能看懂的总结

### 创新二：报告双重用途

同一份 Markdown 报告：
- **人类读**：带 TOC 的分层文档
- **AI 读**：结构化上下文补充。给 AI 读原始 Skill，它只知道「要做什么」；给 AI 读 Skill + 拆解报告，它还知道「为什么这么做、边界在哪里、哪里容易出错」

### 创新三：报告即基础设施

把一批拆解报告丢给 AI 问「能不能组合」，组件清单已标准化，脆弱点已列明，进化线索已存在——**报告把 Skill 压缩成了「接口文档」。**

积累越多，组合进化越轻松，复利效应越明显。

### 创新四：学习与安全审计统一

学习的过程就是审计的过程，审计的发现就是学习的内容。**两件事一次完成。**

---

## ⚠️ 边界与限制

- **输入门槛**：必须是完整实现，不做逆向推断
- **安全审计深度**：基于文本静态分析，无法检测运行时的实际网络行为
- **联动字段**：当前版本联动关系基于本次拆解内的组件
- **拆解深度**：与输入复杂度正相关，简单 Skill 报告自然比复杂的薄
